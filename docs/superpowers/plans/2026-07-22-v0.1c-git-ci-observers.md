# Project Agent Controller v0.1C Git 与 CI 观察器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 v0.1B 基础上增加只读本地 Git 工作树观察和 GitHub/GHES CI 检查观察，并把状态变化接入现有 SourceState、Incident、API 与 Emergency Stop。

**Architecture:** Git 本地状态通过固定参数、无 shell 的 `GitReadTransport` 获取 porcelain v2 输出；GitHub CI 通过严格 GET allowlist 的 HTTP Transport 获取 check-runs 与 combined status。两个 reducer 都将高频快照写入 `SourceStateStore`，只在 transition、failure、recovery 和 heartbeat 时写事件。

**Tech Stack:** Python 3.12–3.13、Pydantic v2、httpx、SQLite WAL、pytest、Ruff、mypy、系统 Git porcelain v2。

## Global Constraints

- v0.1C 仍是 Observer，不修改本地 Git、GitHub、GHES 或业务项目。
- 不允许 fetch、pull、push、commit、reset、checkout、merge、rebase。
- Git Transport 必须 `shell=False`，参数由固定模板生成。
- Git 仓库路径只能来自 `local://` 并限制在 `PAC_LOCAL_REPOS_ROOT`。
- Git ahead/behind 只基于本地 remote-tracking refs，必须标注 `remote_tracking_only=true`。
- GitHub Transport 只允许 check-runs 与 combined status 两个 GET 端点。
- Token 只通过 `env://` 引用，不能进入异常、事件、SourceState 或 API。
- 不下载完整 Actions job logs；只保存受限失败摘要和 details URL。
- Emergency Stop 必须在任何 Git subprocess 或 GitHub HTTP 请求前阻断。
- 稳定 Source 连续 500 次轮询不得产生线性事件增长。
- 完整门禁、真实 GitHub Token 和 GHES 预检完成前 PR 保持 Draft。
