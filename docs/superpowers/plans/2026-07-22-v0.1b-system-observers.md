# Project Agent Controller v0.1B System Observers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add read-only process and Docker lifecycle/log observation to the v0.1A controller while preserving bounded event volume, atomic persistence, local-only security, and Emergency Stop behavior.

**Architecture:** Extend project sources with a discriminated union and dispatch them through focused Source Observer implementations. Process observation uses a `ProcessProvider` backed by psutil; Docker observation uses a GET-only Engine API Provider over a configurable local endpoint. File cursors remain unchanged, while process and Docker sources use a generic JSON `source_states` snapshot table so each polling cycle updates current state without emitting repetitive events.

**Tech Stack:** Python 3.12–3.13, Pydantic v2, psutil 7.x, standard-library Unix socket HTTP, SQLite WAL/FTS5, FastAPI, Typer, pytest.

## Global Constraints

- Runtime remains v0.1 Observer: do not start, stop, restart, exec, signal, or otherwise control business processes or containers.
- Do not execute `ps`, `docker`, shell, test, lint, build, deploy, or arbitrary commands.
- Docker access is GET-only and restricted to an explicit endpoint allowlist.
- Do not read or return container environment variables, secrets, mounts, full labels, or complete process command lines.
- Process selection uses a declared `local://` PID file only in v0.1B.
- Docker selection uses exactly one Compose project/service pair or one exact container name.
- Ambiguous Docker selectors fail closed and never combine logs from multiple containers.
- Every Source is isolated by `(project_id, source_id)`.
- High-frequency polling updates current state but emits events only on transitions, threshold crossings, new logs, provider error changes, or heartbeat deadlines.
- Event, SourceState, and Incident mutations for one observation commit atomically or roll back together.
- Emergency Stop prevents Provider calls and source-state updates.
- Raw logs remain local; Docker log lines pass through existing redaction, Incident, and AI Brief rules.
- Full release verification remains fail-closed until `uv.lock`, Ruff, mypy, pytest, and CLI smoke tests pass.

class ProcessSourceConfig(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    source_id: str = Field(pattern=SOURCE_ID_PATTERN)
    kind: Literal["process"] = "process"
    pid_file_ref: str
    heartbeat_seconds: int = Field(default=300, ge=30, le=86400)
    cpu_warning_percent: float | None = Field(default=None, gt=0, le=10000)
    rss_warning_bytes: int | None = Field(default=None, gt=0)
    include_children: bool = True


class DockerSelector(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    container_name: str | None = None
    compose_project: str | None = None
    compose_service: str | None = None

    @model_validator(mode="after")
    def validate_mode(self) -> "DockerSelector":
        by_name = self.container_name is not None
        by_compose = self.compose_project is not None and self.compose_service is not None
        partial_compose = (self.compose_project is None) != (self.compose_service is None)
        if partial_compose or by_name == by_compose:
            raise ValueError("docker selector must use exactly one selector mode")
        return self


class DockerSourceConfig(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    source_id: str = Field(pattern=SOURCE_ID_PATTERN)
    kind: Literal["docker"] = "docker"

    include_logs: bool = False
    log_tail_on_attach: int = Field(default=100, ge=0, le=5000)
    log_max_lines_per_cycle: int = Field(default=500, ge=1, le=5000)
    heartbeat_seconds: int = Field(default=300, ge=30, le=86400)
    memory_warning_bytes: int | None = Field(default=None, gt=0)
