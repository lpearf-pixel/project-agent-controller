# Project Agent Controller v0.1D Host Service and Community Onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package v0.1C as a safe macOS/Linux host service and onboard Community Selection Miniapp without granting write or execution capabilities.

**Architecture:** A strict dotenv loader imports one permission-checked private environment file before Settings are built. A deterministic renderer produces launchd or systemd user-service files containing only the environment-file path and fixed `pac serve` argv. Community Selection combines Git, CI, and Docker read-only sources in one project declaration; GitHub-hosted release gates verify Linux Docker and macOS service rendering.

**Tech Stack:** Python 3.12–3.13, Typer, pydantic-settings, python-dotenv, launchd plist, systemd user units, Docker Engine GET API, GitHub Actions.

## Global Constraints

- v0.1D remains observer-only and loopback-only.
- Environment files are never evaluated by a shell and secret values are never rendered into service files.
- Existing process environment values override file values.
- Service rendering never installs, enables, starts, stops, or deletes a real service.
- GitHub and Docker transports remain GET-only; Git remains fixed-argv status-only.
- Business repositories, PostgreSQL, payment, refund, inventory, membership, and deployment state are never modified.
