# Project Agent Controller v0.1C Git 与 CI 观察器设计

- 日期：2026-07-22
- 状态：设计基线，已获继续实施授权
- 基础版本：v0.1B Process / Docker Observers
- 分支：`agent/v0.1c-git-ci-observers`

## 1. 目标

v0.1C 在现有 File、Process、Docker Source 之上增加两类只读 Source：

1. `git`：观察本地工作树、HEAD、分支、上游跟踪引用、ahead/behind、冲突和脏状态；
2. `github_ci`：针对 Git Source 当前 HEAD，读取 GitHub/GHES check-runs 与 combined commit status。

最终形成：

```text
本地仓库状态
  + 当前 HEAD
  + CI 检查摘要
  + 历史同类失败
        ↓
SourceState / transition events / Incident / AI Brief
```

## 2. 非目标

v0.1C 明确不实现：

- `git fetch`、`pull`、`push`、`commit`、`reset`、`checkout`、`merge`、`rebase`；
- 自动修改仓库、分支、Index 或工作树；
- 自动重跑 GitHub Actions；
- 创建或更新 Check Run、Commit Status、Issue、PR 或评论；
- 下载完整 Actions job log；
- 执行项目 test/lint/build；
- 调用模型；
- 把 Token、绝对仓库路径或完整 Git 配置写入事件和 API；
- 把本地远端跟踪引用误称为 GitHub 当前远端状态。

## 3. 方案选择

### 方案 A：直接解析 `.git`

优点：不启动外部进程。缺点：需支持 worktree、packed refs、index、pack objects、submodule 和多种 Git 版本，容易误判。

### 方案 B：引入 Dulwich/libgit2

优点：领域接口清晰。缺点：当前离线环境没有依赖；libgit2 增加本地原生依赖，Dulwich 增加新包和兼容门禁。

### 方案 C：固定参数 GitReadTransport + GET-only GitHub Adapter

优点：复用 Git 的稳定 porcelain v2 输出；不需要 shell；可以严格限制命令和网络行为。缺点：依赖本机 `git` 可执行文件。

**采用方案 C。** Git 命令执行集中在一个传输模块，使用绝对可执行路径、固定参数和净化环境；业务层不能提交任意参数。

## 4. 安全边界

### 4.1 GitReadTransport

只允许以下命令模板：

```text
git -c core.fsmonitor=false -c core.untrackedCache=false
    -C <resolved-local-repo>
    status --porcelain=v2 --branch --untracked-files=normal --ignore-submodules=all
```

约束：

- 使用 `subprocess.run([...], shell=False)`；
- 可执行文件在启动时经 `shutil.which("git")` 解析为绝对路径；
- 仓库路径必须来自 `local://`，并限制在 `PAC_LOCAL_REPOS_ROOT` 下；
- 不接收自然语言命令或任意 argv；
- 设置 `GIT_OPTIONAL_LOCKS=0`、`GIT_TERMINAL_PROMPT=0`、`LC_ALL=C`；
- 覆盖 `core.fsmonitor=false`，避免仓库配置触发外部 fsmonitor；
- 忽略 submodule 状态，避免递归执行；
- 设置启动、空闲和总超时；
- stdout/stderr 有硬字节上限；
- 任何未列入模板的 Git 动作直接拒绝。

### 4.2 GitHubReadTransport

只允许 GET：

```text
/repos/{owner}/{repo}/commits/{sha}/check-runs
/repos/{owner}/{repo}/commits/{sha}/status
```

约束：

- repository 必须满足稳定 `owner/name` 格式；
- sha 必须是 40 位十六进制；
- 使用 `Accept: application/vnd.github+json`；
- 使用可配置 `X-GitHub-Api-Version`；
- Token 只通过 `env://VAR_NAME` 解析；
- Token 不进入日志、事件、异常文本和 SourceState；
- 禁止重定向到其他主机；
- 响应体、分页数量和失败摘要均有硬上限；
- 403 rate limit、401/403 auth、404、5xx 和网络失败分类处理；
- 不允许 POST/PATCH/PUT/DELETE。

## 5. 配置模型

### 5.1 Git Source

```yaml
- source_id: repository
  kind: git
  path_ref: local://repos/chan-shuo
  remote: origin
  include_untracked: true
  heartbeat_seconds: 900
```

字段：

- `path_ref`：只允许 `local://`；
- `remote`：默认 `origin`，仅用于解释 porcelain 输出中的 upstream；
- `include_untracked`：默认 true；
- `heartbeat_seconds`：最小 60 秒；
- `max_changed_paths`：默认 0，v0.1C API 默认不返回路径。

### 5.2 SCM Provider

独立文件：`PAC_SCM_PROVIDERS_FILE`。

```yaml
config_version: 1
providers:
  - provider_id: github-cloud
    kind: github
    api_base_url: https://api.github.com
    api_version: 2022-11-28
    credential_ref: env://PAC_GITHUB_TOKEN
    timeout_seconds: 10
```

provider 配置可以版本化；凭据值不能写入配置。

### 5.3 GitHub CI Source

```yaml
- source_id: github-ci
  kind: github_ci
  provider_id: github-cloud
  repository: lpearf-pixel/chan-shuo
  git_source_id: repository
  heartbeat_seconds: 900
  max_check_runs: 100
  max_failed_checks: 20
```

约束：

- `git_source_id` 必须引用同项目内 `git` Source；
- CI 只查询 Git Source 当前 `head_sha`；
- Git Source 没有可用 HEAD 时，CI 不访问网络并写入 blocked 状态；
- 同一项目 Source ID 保持唯一。

## 6. Git SourceState

稳定字段：

```json
{
  "available": true,
  "branch": "agent/v0.1c-git-ci-observers",
  "detached": false,
  "head_sha": "40-hex",
  "upstream": "origin/agent/v0.1c-git-ci-observers",
  "ahead": 1,
  "behind": 0,
  "staged_count": 0,
  "unstaged_count": 2,
  "untracked_count": 1,
  "conflict_count": 0,
  "dirty": true,
  "change_fingerprint": "sha256:...",
  "remote_tracking_only": true,
  "remote_freshness": "unknown"
}
```

不保存：

- 绝对路径；
- Git remote URL；
- 用户名和邮箱；
- 完整 Git config；
- 文件内容；
- 默认情况下的 changed paths。

`ahead/behind` 来自本地现有 remote-tracking ref。必须保留 `remote_tracking_only=true`，防止误认为已经同步远端。

## 7. Git 事件 reducer

首次可用：`git.available`。

状态变化：

- `git.recovered` / `git.missing` / `git.provider.unavailable`；
- `git.head.changed`；
- `git.branch.changed`；
- `git.detached.entered` / `git.detached.cleared`；
- `git.dirty.entered` / `git.dirty.cleared`；
- `git.conflict.entered` / `git.conflict.cleared`；
- `git.ahead.changed` / `git.behind.changed`；
- `git.heartbeat`。

只有 conflict 和 provider 确认的仓库损坏使用 ERROR/CRITICAL 并进入 Incident。普通 dirty、head change 和 ahead/behind 不是故障。

稳定工作树连续 500 次轮询只产生首次 available；跨 heartbeat 窗口后只增加一条 heartbeat。

## 8. CI Provider 归一模型

GitHub check-runs 与 combined status 归一为：

```json
{
  "head_sha": "40-hex",
  "overall": "success|pending|failure|cancelled|neutral|no_checks|unavailable",
  "total_checks": 4,
  "success_count": 3,
  "pending_count": 0,
  "failure_count": 1,
  "failed_checks": [
    {
      "name": "tests",
      "conclusion": "failure",
      "details_url": "https://...",
      "summary": "bounded text",
      "provider_object_id": "123"
    }
  ],
  "legacy_status_state": "success|pending|failure|error|null",
  "etag_check_runs": "...",
  "etag_status": "...",
  "rate_limit_remaining": 4998,
  "rate_limit_reset_at": "RFC3339|null"
}
```

`failed_checks` 数量和 summary 字节数受限；不保存完整 output text 和 job logs。

## 9. CI 聚合规则

优先级：

```text
failure / timed_out / action_required / error
> cancelled
> queued / in_progress / pending
> success
> neutral / skipped
> no_checks
```

combined status 与 check-runs 合并时：

- 任一 failure/error => overall failure；
- 无 failure 且存在 pending => pending；
- 全部 success/neutral/skipped => success；
- check-runs 与 statuses 都为空 => no_checks。

## 10. CI 事件 reducer

- `ci.available` / `ci.recovered` / `ci.unavailable`；
- `ci.auth.failed`；
- `ci.rate_limited`；
- `ci.head.changed`；
- `ci.status.changed`；
- `ci.check.failed`；
- `ci.check.recovered`；
- `ci.no_checks`；
- `ci.heartbeat`。

新进入 failure 的 check 生成 ERROR 事件并进入 Incident；相同 check 在相同 HEAD 上持续失败不重复刷 Incident。

## 11. 条件请求和退避

- 保存 check-runs 与 status 两个 ETag；
- 下次请求发送 `If-None-Match`；
- 304 使用上次状态，不生成变化事件；
- rate limit 剩余为 0 时，保存 reset 时间并在该时间前跳过 Provider；
- 401/403 auth 错误采用固定退避并合并事件；
- 网络/5xx 使用有上限指数退避；
- Emergency Stop 在退避检查和 Provider 调用之前生效。

## 12. 数据流

```text
ObserverDaemon
  -> ObserverRunner
      -> GitSourceObserver
          -> GitReadTransport
          -> SourceStateStore
      -> GitHubCISourceObserver
          -> read Git SourceState.head_sha
          -> GitHubReadTransport
          -> SourceStateStore
          -> Incident candidates
```

项目 Source 顺序不作为依赖保证。Runner 对同项目先处理 File/Process/Docker/Git，再处理 CI；CI 仍会验证依赖 State 存在。

## 13. API 和 CLI

现有 API 已可返回 SourceState，无需新增高权限接口。

增加只读过滤：

```text
GET /v1/projects/{project_id}/sources?kind=git
GET /v1/projects/{project_id}/sources?kind=github_ci
```

CLI：

```text
pac sources <project-id> --kind git
pac sources <project-id> --kind github_ci
```

输出不包含 Token、API Authorization header、绝对仓库路径和 Git remote URL。

- ETag/304；

- 相同失败去重与恢复；

### 集成

- 同项目 Git 先于 CI；
- 项目间 SourceState 隔离；
- Event/Incident/SourceState 原子提交；
- API/CLI 无敏感字段；
- Git Source 不执行网络命令；
- CI Transport 不允许写方法。
