# v0.2 Controlled Runner Design

## Goal

Add a local, auditable runner for explicitly configured verification commands. The runner
must not modify a registered business worktree and must remain subordinate to the global
controller state.

## Safety boundary

- A task template contains a fixed executable and fixed argument vector. Callers cannot
  append arguments, inject environment values, or request a shell.
- The source repository is addressed through `local://` below `PAC_LOCAL_REPOS_ROOT`.
- Every attempt runs from a temporary `git archive HEAD` extraction. Untracked files,
  ignored files, `.git`, local secrets, and worktree changes are excluded.
- The child environment is rebuilt from a small deterministic baseline plus literal
  template values. Credential-shaped keys and values containing NUL are rejected.
- Execution uses `shell=False`, starts a process group, has a wall-clock timeout, and
  terminates the whole process group on timeout.
- Captured stdout and stderr are bounded and UTF-8 decoded with replacement. Absolute
  archive paths are replaced before persistence or display.
- Only `ACTIVE` permits a new task. Drain, emergency stop, recovery, and degraded states
  fail closed before `git archive` or the configured executable starts.
- A request has a caller-provided idempotency key. Repeating a completed request returns
  its prior terminal result without a second process.
- A task may retry at most three attempts. Three consecutive failed task requests open a
  per-project circuit. After the cooldown exactly one half-open probe is allowed.
- v0.2 never commits, pushes, deploys, modifies a database, edits source, or invokes AI.

## Configuration

Projects gain a `tasks` list. Each task declares:

- stable `task_id`;
- `repository_ref` and optional archive-relative `working_directory`;
- fixed `executable` and fixed `arguments`;
- literal environment mapping;
- timeout, maximum attempts, output byte limit, and circuit policy.

The committed Community Selection example initially exposes only its frozen repository
verification command. Payment, refund, inventory mutation, migrations, production
deployment, and SCM writes are deliberately absent.

## Persistence and API

SQLite stores one task request plus bounded attempts. The request records project, task,
idempotency key, state, timestamps, exit classification, and sanitized output. Attempts
record their number and terminal evidence. Circuit state is persisted per project.

v0.2 exposes a local CLI command:

```text
pac task run PROJECT_ID TASK_ID IDEMPOTENCY_KEY
```

The command prints a bounded JSON result. No remote execution endpoint is introduced.

## Failure model

Configuration and policy errors do not retry. A non-zero exit or timeout may retry within
the configured limit. Exhaustion records a failed request and advances the circuit.
Success closes the circuit and resets consecutive failures. Workspace creation failures
are recorded as infrastructure failures without exposing host paths.

## Acceptance criteria

- injection, path escape, secret-environment, archive traversal, timeout, process-group
  cleanup, output limit, idempotency, retry, circuit, and controller-stop tests pass;
- Community Selection has a committed verification-only task template;
- the public Ubuntu/macOS release gate exercises a real temporary Git repository and a
  fixed command without touching its source worktree;
- all prior v0.1D verification remains green.
