# Project Agent Controller v0.1B System Observers Design

- 日期：2026-07-22
- 状态：批准后执行的增量设计
- 基线：`agent/v0.1a-bootstrap`
- 实现分支：`agent/v0.1b-system-observers`

## 1. 目标

v0.1B 在 v0.1A 文件日志观察闭环上增加两类只读观察源：

1. 本机进程生命周期与资源状态；
2. Docker 容器生命周期、健康状态和可选 stdout/stderr 日志。

系统继续遵守 Observer 边界：不启动、停止、重启或杀死业务进程与容器，不执行项目命令，不读取容器环境变量、密钥、挂载明细或完整命令行，不写入业务 Git 仓库。

## 2. 方案比较

### 方案 A：直接调用 `ps`、`docker ps` 和 `docker logs`

优点是实现快。缺点是引入 shell、不同平台输出不稳定、难以做精确游标和测试，也容易在参数拼接时穿透任意命令边界。

### 方案 B：直接在业务逻辑中依赖 psutil 和 Docker SDK

优点是 API 丰富。缺点是 Provider 与领域逻辑耦合，Docker SDK 增加较重依赖，离线环境和私有 Docker Endpoint 的测试不稳定。

### 方案 C：Provider Port + psutil + 只读 Docker Engine Client

核心只依赖 `ProcessProvider` 和 `DockerProvider` 协议。默认进程实现使用 psutil；Docker 实现通过标准库 Unix Socket HTTP 客户端访问硬编码 GET 接口。测试使用 Fake Provider。

**采用方案 C。** 它保持核心可测试、支持 Mac/Linux、不会引入任意 shell，并能在以后替换为 Docker Socket Proxy、Podman 或远程只读代理。

## 3. 范围

### 3.1 v0.1B 包含

- `process` 日志源类型；
- `docker` 日志源类型；
- 泛化的 Source 配置联合类型；
- 通用 `source_states` 快照表；
- 进程 PID 文件解析和 PID 复用识别；
- 进程状态、CPU、RSS、子进程数采样；
- Docker Compose 标签或精确容器名选择；
- 容器 state、health、restart count、exit code、OOMKilled；
- Docker stdout/stderr 的有限增量日志读取；
- 高频快照、低频事件的合并规则；
- 本地 API 中的当前 Source 状态查询；
- 首批项目接入模板和预检命令；
- Emergency Stop 对全部 Source Observer 生效。

### 3.2 v0.1B 不包含

- 杀进程、停止或重启容器；
- Docker POST/PUT/DELETE 请求；
- 容器 exec；
- 任意 shell 命令；
- 读取容器环境变量、secret、mount、完整 labels；
- 自动修复、扩容或部署；
- Git、CI watcher；
- 远程 Agent 节点；
- Prometheus 或长期时序数据库。

## 4. 配置模型

`ProjectConfig.sources` 改为带 `kind` 判别器的联合类型：

```text
FileSourceConfig
ProcessSourceConfig
DockerSourceConfig
```

### 4.1 ProcessSourceConfig

v0.1B 只允许 PID 文件定位，避免按模糊名称误匹配其他项目：

```yaml
- source_id: importer-process
  kind: process
  pid_file_ref: local://person-relation/importer.pid
  heartbeat_seconds: 300
  cpu_warning_percent: 90
  rss_warning_bytes: 8589934592
  include_children: true
```

约束：

- `pid_file_ref` 必须使用 `local://`；
- PID 文件只能包含一个十进制正整数；
- 不支持进程名模糊搜索；
- 进程身份由 `pid + create_time` 共同确定；
- 不保存完整 cmdline，只保存 process name 和 executable basename。

### 4.2 DockerSourceConfig

```yaml
- source_id: database-container
  kind: docker
  selector:
    compose_project: person-relation-lab
    compose_service: db
  include_logs: true
  log_tail_on_attach: 100
  log_max_lines_per_cycle: 500
  heartbeat_seconds: 300
  memory_warning_bytes: 26843545600
```

也可使用唯一的 `container_name`：

```yaml
selector:
  container_name: person-relation-lab-db-1
```

约束：

- Compose project/service 与 container name 二选一；
- 选择结果必须为零个或一个容器；
- 多个匹配视为 `docker.selector.ambiguous`，不混合日志；
- Docker Endpoint 在本机 Settings 中配置，不进入项目仓库；
- `include_logs=false` 时仅观察生命周期和健康状态。

## 5. Provider 接口

### 5.1 ProcessProvider

```python
class ProcessProvider(Protocol):
    def snapshot(self, pid: int) -> ProcessSnapshot: ...
```

`ProcessSnapshot` 只包含：

- PID；
- create time；
- status；
- process name；
- executable basename；
- CPU time；
- RSS bytes；
- child count。

默认 `PsutilProcessProvider` 将 `NoSuchProcess`、`AccessDenied` 和 zombie 分别归一为明确结果，不把异常栈直接外发。

### 5.2 DockerProvider

```python
class DockerProvider(Protocol):
    def find_container(self, selector: DockerSelector) -> DockerContainer | None: ...
    def inspect(self, container_id: str) -> DockerSnapshot: ...
    def logs(self, container_id: str, cursor: DockerLogCursor, limit: int) -> DockerLogBatch: ...
```

默认 `DockerEngineClient` 只允许：

- `GET /_ping`；
- `GET /containers/json`；
- `GET /containers/{id}/json`；
- `GET /containers/{id}/logs`。

任何非 GET 请求或未列入允许表的路径都在客户端内部拒绝。

## 6. 状态与事件模型

### 6.1 source_states

新增通用当前状态表：

```text
project_id
source_id
source_kind
sequence
state_json
observed_at
updated_at
```

它是当前快照，不替代追加事件。不同项目和 Source 使用复合主键隔离。

### 6.2 进程事件

- `process.missing`：首次无法找到 PID 文件或进程；
- `process.available`：缺失后恢复；
- `process.restarted`：PID 或 create time 改变；
- `process.state.changed`：running/sleeping/zombie 等状态变化；
- `process.resource.threshold`：CPU/RSS 首次跨越阈值；
- `process.resource.recovered`：回落到带滞回的安全区；
- `process.heartbeat`：固定时间窗口的有限摘要；
- `process.access.denied`：首次权限不足，后续合并。

### 6.3 Docker 事件

- `docker.container.missing`；
- `docker.container.available`；
- `docker.selector.ambiguous`；
- `docker.state.changed`；
- `docker.health.changed`；
- `docker.container.restarted`；
- `docker.container.exited`；
- `docker.container.oom_killed`；
- `docker.resource.threshold` / `docker.resource.recovered`；
- `docker.heartbeat`；
- `docker.log.line`。

Docker 日志沿用 v0.1A 的 severity 分类、错误指纹、Incident 聚合、脱敏和 AI Brief。

## 7. 高频采样与日志精简

每轮观察都会更新 `source_states`，但不会每轮写事件。

事件触发条件：

1. Source 第一次出现或消失；
2. 生命周期、health、PID/create time、restart count 或 exit/oom 状态变化；
3. CPU/RSS 等指标从安全区跨越警戒阈值；
4. 指标从警戒区回落至 90% 阈值以下；
5. 达到 heartbeat 时间；
6. 出现新的 Docker 日志行；
7. Provider/Selector 首次失败或错误类型发生变化。

重复失败和重复阈值不会按轮询频率刷事件。快照仍保留最新数值，API 可直接查询。

Docker 日志规则：

- 请求必须启用 timestamps；
- 只接受带 RFC3339 时间戳的完整行；
- 每轮最多读取配置行数；
- Cursor 保存最后时间戳和同时间戳近期哈希；
- 重连或 Engine 重复返回时按时间戳+内容哈希去重；
- 首次接入只取 `log_tail_on_attach`，不回灌全部历史；
- 单行仍受 AI Brief 和脱敏规则限制。

## 8. Runner 集成

`ObserverRunner` 保持项目级互斥，按 Source kind 分发：

```text
file    -> FileSourceObserver
process -> ProcessSourceObserver
Docker  -> DockerSourceObserver
```

每个 Observer 返回：

- 追加事件；
- 新 SourceState；
- 可选 Incident candidates。

数据库通过单个事务提交事件、状态和 Incident；任何失败整体回滚。

## 9. 安全模型

- 默认 Docker Socket 位置来自 `PAC_DOCKER_SOCKET`；
- 推荐 rootless Docker Socket 或只读 Socket Proxy；
- 直接 Docker Socket 访问在文档中标为高权限本地集成；
- Docker 客户端只有硬编码 GET allowlist；
- Provider 不返回环境变量、secret、mount 或完整 label 集；
- 进程观察不返回完整 cmdline；
- v0.1B API 没有 process/container stop、restart、exec 路由；
- Emergency Stop 后 Provider 不再被调用；
- 所有配置未声明 Source 默认忽略。

## 10. 首批项目接入

公开仓库提供无真实路径的模板；私有知识仓库保存项目 Profile 和经验证的 selector，但不保存原始日志。

首批接入顺序：

1. `person-relation-lab`：数据库容器、应用容器、导入进程；
2. `community-selection-miniapp`：API 和 Admin 容器；
3. `chan-shuo`：本地开发/runner 进程；
4. `kanyu-spatial-engine`：后续构建或测试进程；
5. `chinese-star-omen-workspace`：知识库服务进程。

每个项目接入前执行 preflight：

- selector 唯一；
- PID 文件可读且 PID/create time 有效；
- Docker Endpoint 可读；
- 不读取敏感字段；
- 观察两个周期不会产生重复状态事件；
- Emergency Stop 后事件数不再增长。

## 11. 测试矩阵

### 配置

- Source 联合类型反序列化；
- PID 文件必须是 local ref；
- Docker selector 二选一；
- 重复 source ID 被拒绝；
- 不支持的 Source kind 被拒绝。

### Process

- 首次 available；
- missing 去重与恢复；
- PID reuse/restart；
- status transition；
- CPU/RSS 阈值跨越与恢复；
- access denied 合并；
- 不暴露完整 cmdline。

### Docker

- Compose label 精确匹配；
- container name 精确匹配；
- 多匹配 fail-closed；
- state/health/restart/exit/OOM transitions；
- 日志时间游标和重复去重；
- 单轮日志上限；
- GET allowlist，非 GET 拒绝。

### 集成

- File/Process/Docker 在同一项目运行；
- 不同项目同名 Source 不共享状态；
- 事件、SourceState、Incident 同事务回滚；
- 500 个无变化轮询只产生有限 heartbeat；
- Emergency Stop 阻断全部 Provider；
- API 不返回私有绝对路径和敏感 Docker 字段。

## 12. 验收标准

v0.1B 完成需满足：

- v0.1A 全部回归测试继续通过；
- 新增 Process/Docker 单元和集成测试通过；
- 离线验证脚本覆盖 psutil Provider 与 Fake Docker Provider；
- 没有业务控制动作或任意 shell；
- 高频采样不会线性放大事件数量；
- Docker 日志可进入现有 Incident/AI Brief；
- 首批至少一个 Docker 项目和一个本机进程完成本地 preflight；
- 完整 Ruff/mypy/lock 门禁未满足前 PR 保持 Draft。
